# Deployment Guide - Render

This guide provides step-by-step instructions for deploying the E-Sign Application to Render.

## Prerequisites

- GitHub/GitLab repository with your code
- Render account (sign up at https://render.com)

## Configuration Files

The following files are included for Render deployment:

- `render.yaml` - Blueprint configuration for all services
- `build.sh` - Build script executed during deployment
- `gunicorn_config.py` - Production Gunicorn configuration
- `.renderignore` - Files to exclude from deployment
- `Procfile` - Alternative service definitions

## Quick Deploy (Using Blueprint)

1. **Push your code to GitHub/GitLab**
   ```bash
   git add .
   git commit -m "Add Render deployment configuration"
   git push origin main
   ```

2. **Deploy via Render Dashboard**
   - Go to https://dashboard.render.com
   - Click "New +" → "Blueprint"
   - Select your repository
   - Render will automatically detect `render.yaml`

3. **Update Environment Variables**
   Before deploying, update these in the Render dashboard:
   - `ALLOWED_HOSTS`: Your Render app domain (e.g., `your-app-name.onrender.com`)
   - `CORS_ALLOWED_ORIGINS`: Your frontend URL(s), comma-separated

4. **Optional Environment Variables** (set in Render dashboard):
   - `SENTRY_DSN`: If using Sentry for error tracking
   - `EMAIL_*`: Email configuration variables
   - `AWS_*`: If using S3 for media storage
   - `USE_S3`: Set to `True` to enable S3 storage

5. **Deploy**: Render will automatically build and deploy all services

## Services Created by Blueprint

The `render.yaml` blueprint creates:

1. **Web Service** (`esign-web-app`)
   - Django application served by Gunicorn
   - Health check at `/health/`
   - Auto-scales based on traffic

2. **PostgreSQL Database** (`esign-database`)
   - Production database
   - Automatic backups
   - Connection string auto-linked

3. **Redis Instance** (`esign-redis`)
   - Used for Celery broker and caching
   - Connection string auto-linked

4. **Celery Worker** (`esign-celery-worker`)
   - Background task processing
   - Handles notifications and async tasks

## Manual Service Setup (Alternative)

If you prefer to create services manually:

### 1. Create PostgreSQL Database

- **Name**: `esign-database`
- **Database**: `esign_db`
- **User**: `esign_user`
- Note the **Internal Database URL** for later use

### 2. Create Redis Instance

- **Name**: `esign-redis`
- Note the **Internal Redis URL** for later use

### 3. Create Web Service

- **Name**: `esign-web-app`
- **Environment**: Python 3
- **Build Command**: `./build.sh`
- **Start Command**: `gunicorn esign.wsgi:application --bind 0.0.0.0:$PORT`

**Environment Variables**:
```
PYTHON_VERSION=3.12.0
DATABASE_URL=<Internal Database URL from PostgreSQL service>
SECRET_KEY=<Generate a strong random key>
DEBUG=False
ALLOWED_HOSTS=your-app-name.onrender.com
CORS_ALLOWED_ORIGINS=https://your-frontend-domain.com
CELERY_BROKER_URL=<Internal Redis URL>
CACHE_LOCATION=<Internal Redis URL>
```

### 4. Create Background Worker (Celery)

- **Name**: `esign-celery-worker`
- **Environment**: Python 3
- **Build Command**: `./build.sh`
- **Start Command**: `celery -A esign worker -l info`

Use the same environment variables as the web service.

## Post-Deployment Checklist

- [ ] Update `ALLOWED_HOSTS` with your actual Render domain
- [ ] Configure `CORS_ALLOWED_ORIGINS` with your frontend URL(s)
- [ ] Set up email configuration (if needed)
- [ ] Configure S3 storage (if using cloud storage)
- [ ] Set up Sentry (optional, recommended for production)
- [ ] Verify health check endpoint: `https://your-app.onrender.com/health/`
- [ ] Test all API endpoints
- [ ] Verify Celery worker is processing tasks
- [ ] Set up monitoring alerts

## Custom Domain Setup

1. In Render dashboard, go to your web service
2. Navigate to "Settings" → "Custom Domains"
3. Add your domain
4. Update DNS records as instructed by Render
5. Update `ALLOWED_HOSTS` to include your custom domain

## Troubleshooting

### Build Failures
- Check build logs in Render dashboard
- Ensure all dependencies are in `requirements.txt`
- Verify `build.sh` is executable

### Database Connection Issues
- Verify `DATABASE_URL` is correctly set
- Check if PostgreSQL service is running
- Verify connection string format

### Celery Not Working
- Ensure Redis service is running
- Check `CELERY_BROKER_URL` is correctly set
- Verify Celery worker service is running

### Static Files Not Loading
- Ensure `collectstatic` runs during build (in `build.sh`)
- Check static files are served correctly
- Consider using CDN for static files

## Environment Variables Reference

### Required
- `DATABASE_URL`: PostgreSQL connection string (auto-set by Blueprint)
- `SECRET_KEY`: Django secret key (auto-generated by Blueprint)
- `DEBUG`: Set to `False` in production
- `ALLOWED_HOSTS`: Your Render domain(s)

### Recommended
- `CORS_ALLOWED_ORIGINS`: Frontend URL(s)
- `CELERY_BROKER_URL`: Redis URL for Celery (auto-set by Blueprint)
- `CACHE_LOCATION`: Redis URL for caching (auto-set by Blueprint)

### Optional
- `SENTRY_DSN`: Error tracking
- `EMAIL_*`: Email configuration
- `AWS_*`: S3 storage configuration
- `USE_S3`: Enable S3 storage (`True`/`False`)
